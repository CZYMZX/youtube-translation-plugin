# 术语库 / 翻译场景 上传规范（v0.2.9）

适用版本：v0.2.9 及以后。上传入口：设置面板 →「术语与场景」页 → 各区块右上角「＋ 上传」或各卡片「上传」。

上传文件均为 **UTF-8 编码的 JSON**（单文件 ≤ 1 MB），校验失败会给出具体行号与原因，不会入库。

---

## 一、术语库上传规范

### 1.1 文件结构

```json
{
  "version": 1,
  "name": "MC 游戏术语库",
  "description": "Minecraft 方块 / 生物 / 机制",
  "entries": [
    {
      "ja": "クリーパー",
      "zh": "苦力怕",
      "en": "Creeper",
      "category": "term",
      "source": "https://zh.minecraft.wiki/",
      "sourceType": "wiki"
    }
  ]
}
```

| 字段 | 必填 | 类型/限制 | 说明 |
|---|---|---|---|
| `name` | ✅ | 字符串，1~40 字 | 术语库名称；与内置类别同名时自动加「（自定义）」后缀 |
| `entries` | ✅ | 数组，1~2000 条 | 术语条目列表 |
| `description` | 否 | 字符串 | 列表页展示的描述 |
| `version` | 否 | 数字 | 建议填 `1`，便于后续兼容 |

### 1.2 条目字段

| 字段 | 必填 | 限制 | 说明 |
|---|---|---|---|
| `ja` | ✅ | 1~60 字 | 日文原词，**匹配主键**；翻译时按子串匹配原文 |
| `zh` | ✅ | 1~120 字 | 中文译名（会强制 AI 使用） |
| `en` | 否 | 字符串 | 英文/罗马字，仅展示与检索 |
| `category` | 否 | `talent` / `group` / `game` / `song` / `term` | 缺省按 `term` |
| `source` | 否 | 字符串（建议 URL） | 来源；缺省记为「用户上传」 |
| `sourceType` | 否 | `official` / `wiki` / `community` | 来源类型，缺省 `community` |

> `needsContext` 是**内置包专用**的语境门控字段（同一句里还必须命中 ≥1 条普通术语才注入；两个门控词同句不互相作证），上传包即使写了也会被忽略；自定义包里遇到 `修繕` 这类高频日常词，请把 `ja` 写成更长、不会在口语中误撞的写法（如 `修繕つき`），或干脆不收录。

### 1.3 编写要求

1. **`ja` 必须是原文中会真实出现的写法**（含假名/汉字），否则匹配不到；同一术语有多种写法时，拆成多条。
2. **一条术语只放一个译名**；同一原词的不同译法会互相冲突（后者覆盖前者）。
3. **单字汉字术语也参与匹配**（如 `土` / `石` / `砂` / `盾`），但要求左右邻接都不是汉字——`土を掘る` 命中，`土曜日` / `宝石` / `砂漠` / `氷点下` / `弓道` 不误命中；多字术语仍为纯子串匹配，注入时按日文长度降序、每批最多 40 条。
4. 译名不要带括号注释（如 `苦力怕（Creeper）`），否则字幕里也会出现括号。
5. 单包建议 ≤ 500 条；条目越多，命中注入的 prompt 越长（每批最多注入 40 条）。
6. 分类含义：`talent` 主播/人物、`group` 团体/组合、`game` 游戏名、`song` 歌曲名、`term` 其余用语。

### 1.4 校验规则（不通过即拒绝）

- 缺 `name` / `name` 为空 / 超 40 字
- `entries` 非数组、为空、超过 2000 条
- 任一条目缺 `ja` 或 `zh`，或超长
- 文件不是合法 JSON / 不是对象

## 二、翻译场景上传规范

### 2.1 文件结构

```json
{
  "version": 1,
  "name": "科普视频",
  "description": "科学解说 / 教育内容",
  "hint": "例：TED-Ed、物理讲解",
  "prompt": "你是一位科普视频字幕译者。要求：术语准确并使用业界通用译名；逻辑连接词清晰；保留公式、单位与数字原样；不添加原文没有的信息；语气客观、面向大众读者。"
}
```

| 字段 | 必填 | 限制 | 说明 |
|---|---|---|---|
| `name` | ✅ | 1~40 字 | 场景名称，列表展示 |
| `prompt` | ✅ | 20~4000 字 | 场景提示词，作为 system prompt 的场景段注入 |
| `description` | 否 | 字符串 | 场景说明 |
| `hint` | 否 | 字符串 | 示例（如适合的视频类型） |
| `version` | 否 | 数字 | 建议 `1` |

**不允许未知字段**（防止拼写错误被静默忽略）。

> 设置页 →「翻译场景」分区里有一份**同一口径**的折叠说明（默认收起），
> 以及「用 AI 生成模板」按钮给出的提示词模板。文件、界面、本文档三处只有一套说法：
> 字段名、限制、示例 JSON、常见错误都逐字相同，改规范时三处一起改。

### 2.2 prompt 编写要求

一份合格的场景提示词应包含 5 个要素：

1. **角色**：你是什么译者（VTuber 熟肉 / 科普字幕 / 歌词译者…）；
2. **受众与语气**：面向谁、正式还是口语、是否需要保留礼貌层级；
3. **术语策略**：专有名词保留原文 / 统一译名 / 不括注；
4. **格式与数字**：单位、数字、公式、时间格式如何处理；
5. **禁止事项**：不得增删事实、不得解释剧情、不得输出多句合一。

示例（可直接改写使用）：

```
你是一位【音乐视频】字幕译者，面向中文听众翻译日文歌词与 MC 串场。
要求：歌词意译优先、尽量押韵、保留重复段结构；人名/歌名等专名保留原文不译
（术语库已给出译名的条目以术语库为准），其余内容一律译成目标语言；
译文长度贴近原歌词、逐行对应，节奏与原语言对齐；数字与时间保持原样；
不添加原文没有的解释；每行译文不得超过原文行数。
```

### 2.3 校验规则（不通过即拒绝）

- 缺 `name` 或 `prompt`
- `name` 超过 40 字
- `prompt` < 20 字（无法有效指导翻译）或 > 4000 字
- 含未知字段
- 文件不是合法 JSON / 不是对象

### 2.4 常见错误（报错原文 → 怎么改）

| 现象 | 原因 | 处理 |
|---|---|---|
| `缺少字段 prompt（场景提示词）` | 顶层只有 `name`，忘了写 `prompt` | 补一个 20~4000 字的提示词 |
| `prompt 少于 20 字，无法有效指导翻译` | 只写了一句「翻译得好一点」 | 按 5 个要素补全：角色、受众语气、术语策略、格式数字、禁止事项 |
| `prompt 超过 4000 字` | 把整篇文档 / 整段聊天记录贴进来了 | 只保留「这类视频该怎么译」的行为约束 |
| `文件内容不是 JSON 对象` | 交的是数组、纯文本、空文件 | 顶层必须是 `{ … }`，不是 `[ … ]` |
| `存在未知字段：promt, instruction` | 键名拼错，或用文档里的说法当键名 | 只留 `version` / `name` / `description` / `hint` / `prompt` 五个字段 |
| `version` 写成了 `2` | 当前只认 `1`，但**不会因此被拒**（校验不看这个字段的值） | 改成 `1`；非 1 也没有任何升级含义 |

## 三、生效与缓存

- 术语库：上传后自动出现在列表并**自动启用**；勾选/取消即时生效。启用包的合集变化会触发翻译缓存键变化，旧译文自动失效。
- **缓存按内容判定（v0.4.1）**：每个包各自生成内容指纹（内置包内容 hash；自定义包 `id:内容hash`，旧版只记 `id:条目数`）。因此**只改译名、条数不变**的修改同样让旧译文失效——在术语库编辑器里改完一个译名，相关内容不再返回旧译法（自定义包改动需等 10 秒的包刷新 TTL 生效，随后重看/重译即用新译名）。改 `source` / `en` / 描述这类不参与译文的元数据**不会**触发失效。
- 失效范围只覆盖**已启用**的包：未启用的包内容变化不影响缓存。详见 `GLOSSARY-CACHE-TAG.md`。
- 场景：上传后出现新卡片，点击「使用」切换；场景 id + 提示词指纹参与缓存键，修改 prompt 后旧译文自动失效。
- **设置页的入口写的是同一份存储**：「翻译场景」分区的「＋ 新建场景」「导入 JSON」与弹窗的场景卡片共用
  `yt_sub_custom_scene_packs`（术语库共用 `yt_sub_custom_glossary_packs`）。新建与导入都**不会**自动切换
  正在使用的场景——列表里选中只是「查看」，换用要显式点右侧的「使用此场景」。
- 内置类别（VTuber / 通用日常 / MC / AI 等）不可删除；上传同名包会生成「（自定义）」副本。

## 四、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 上传提示「entries 必须是非空数组」 | 用了 `terms` / `items` 等字段名 | 改为 `entries` |
| 术语没生效 | `ja` 与原文写法不一致（如原文是片假名，条目写汉字） | 按原文写法补一条 |
| 场景选中后语气没变化 | prompt 少于 20 字被拒 / 未点「使用」 | 补全 prompt 并点击「使用」 |
| 译名出现括号原文 | 译名里手写了括号 | 去掉括号，仅保留中文 |
