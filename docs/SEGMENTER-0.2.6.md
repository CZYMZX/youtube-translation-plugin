# 断句引擎 v0.2.6 —— 语言分策略改造说明

日期：2026-11-04
目录：`E:\Antigravity\油管翻译插件_v0.2.6`（v0.2.5 保持存档不动）

## 一、改造目标

1. 不同语言使用对应断句策略（日语语法 / 英语标点空格 / 中文标点 / 其他语言兜底）；
2. 减少错误断句与漏断句（68 秒长句、`，。` 伪影、短碎片、时间轴重叠）；
3. 断句相关新选项融入设置面板「断句引擎」标签页，样式与现有界面一致。

## 二、架构

```
timedtext JSON3
   │ extractCaptionTokens()          ← 噪声过滤（[Music]/署名行）、标点子拆分、停顿信号重建
   ▼
CaptionToken[]
   │ detectStreamLanguage()          ← 假名/谚文/汉字/拉丁统计 → ja/zh/ko/en/generic
   ▼
LanguageProfile                      ← 语言策略参数包（单位制/日语语法/英语语法/最小断句单位）
   │ segmentCaptionTokens()          ← 9 条规则（4 条硬约束优先）
   ▼
后处理：纯标点句过滤（flush 时）→ 短碎片合并 → 时间轴去重叠 → 重编号
```

### 规则顺序（前者优先）

| # | 规则 | 类型 |
|---|---|---|
| 1 | 句末终止标点（。！？… ；英语含缩写保护） | 软 |
| 2 | 超长停顿 >= max(2×阈值, 800ms) | **硬** |
| 3 | 时长 >= maxDurationMs | **硬** |
| 4 | 长度 >= 上限（CJK 字数 / 拉丁词数） | **硬** |
| 5 | 常规停顿 >= pauseThreshold + 最小单位 | 软 |
| 6 | 日语句末助词 + 轻停顿/新句叹词 | 软（ja） |
| 7 | 日语接续助词 + 中停顿 | 软（ja） |
| 8 | 新句开头词（英语强连词 / 日语叹词）+ 停顿 | 软 |
| 9 | 英语弱连词 + 中停顿 | 软（en） |

原版 bug：规则 2 内「组不足 4 字则不断」会短路掉规则 7 的时长上限，33 秒静音被整句吞掉（实测 68s 句）。v0.2.6 将硬约束前置且无条件触发。

## 三、语言策略细节

### 语言判定阈值（detectStreamLanguage，整轨字符统计）

原先只写了「按假名/谚文/汉字/拉丁统计判定」，具体阈值未入文档。2026-11-06 按 `utils/segmenter.ts` 核对补齐：

| 判定 | 条件（整轨计数，按 Unicode 码点逐字累加） |
|---|---|
| ja | 假名 ≥3 |
| ko | 谚文 ≥3 且 谚文 > 汉字 |
| zh | 汉字 ≥4（且不满足 ja/ko） |
| en | 拉丁字母 ≥12 且 拉丁 > 汉字 |
| generic | 其余（含空轨） |

判定按上表顺序短路，`segmentationLanguage` 非 `auto` 时跳过检测直接采用用户指定语言。

### 日语（ja）
- 句末助词表新增单独「ね/よ/な/わ/ぞ」（VTuber 高频，需组内 >=8 字 + 轻停顿或新句叹词配合，避免误触发）；
- 助词匹配先剥离尾部标点（「ですね。」也能命中）；
- 疑问句：以「か」结尾且不在「かも/から/かしら/かな/だろう/でしょう」排除名单 → 补「？」。

### 中文（zh）
- 不套用任何日语助词规则；依靠标点 + 停顿 + 字数/时长硬上限。

### 英语（en）
- 缩写保护（Mr./e.g./U.S. 等不因句点断句）；
- 强连词（however/therefore…）与弱连词（and/but/so…）分级断句；
- 疑问起始词（what/is/can…）补问号。

## 九、v0.4.2 括号短词策略：歧义短词如实保留（2026-11-06）

> 状态：**改动留在工作区，未 commit / tag / push**。

### 9.1 用户口径与缺陷

用户原话：「音、笑、SE 这类短词，（音）、（笑）等就如实表达，比如"今天天气真好啊（笑）"」。

缺陷：`NOISE_SOUND_WORDS` 里含 `音` / `笑` / `se`（以及同为单字的 `咳`），这三/四个条目会让**整行**被当作噪声剔除，于是「今天天气真好啊（笑）」这类行的话轮标记与情绪信息直接丢失，且该句不再进入翻译。

### 9.2 划线依据（为什么是这几个、为什么不是按字数）

判据不是字数，是「括号内文能否**唯一**读作非言语音效」：

1. **语义不可判定**：单字内文没有构词成分（`〜声` `〜音` `〜息`）可供判断它是音效名词、实词、缩写还是注释；而词表保留的条目（`笑い声` / `拍手` / `ため息` / `息をのむ音`）都是**自身即音效名词**的完整词，单独出现时在字幕流里没有指称功能，删掉不损失语义。
2. **用户口径**：（音）（笑）（SE）是随话语同步的副语言标记，属于要如实表达的内容，不是噪声。
3. **代价不对称**：误留 = 多一行标记（可读、可忽略）；误删 = 丢语义且该句不再送翻译（不可逆）。与断句侧「宁可漏切不可劈词」同源 ⇒ 宁可漏删不可误删。

因此规则写成**结构性豁免 + 词表精简**两道：

| 层 | 规则 |
|---|---|
| 结构性豁免 `isAmbiguousShortInner()` | 内文**整体**为 1 个 CJK 字（含假名/汉字），或 1~2 个拉丁字母 ⇒ 一律保留 |
| 词表精简 | 移除因此变成死条目的 `音` / `笑` / `se` / `咳`（保留也无意义，命中前已被豁免拦下） |

**仍剔除的音效长词**（2 字起、自身即音效名词）：`笑い` `笑い声` `叫び声` `悲鳴` `鼻息` `うめき声` `息をのむ音` `泣き声` `ため息` `溜息` `吐息` `あくび` `号泣` `嗚咽` `拍手` `音楽` `歓声` `効果音` `無音` `沈黙` `咳払い` `舌打ち` `足音` `物音` `ざわめき` `bgm`；英语 `(Laughter)` `(Applause)` `(Cheering)`…；中文 `（笑声）` `（鼓掌）` `（掌声）`…。多重标记逐段判定不变（`[ため息][息をのむ音]` 整体剔除）；纯符号（`（♪）`）仍剔除；专名/术语（`（Glaxo Smith Kline）` `（NNT）`）不受影响。

### 9.4 边界与风险

- 单字豁免是**宽度换安全**：若某条轨高频出现 `[咳]` `[音]` 这类真音效标记，会留下噪音行；本语料实测 0 处，风险未发生，如需再收紧应按真实语料复议，不能按字数重划。
- 韩语、其他轨未测（无对应语料）；规则与语言无关（纯结构判定）。
- 括号内文若为 2 个字且不在词表（如 `（拍手音）`），仍按「含真实文字即保留」处理——这是 v0.4.1 既有取舍，未改。
